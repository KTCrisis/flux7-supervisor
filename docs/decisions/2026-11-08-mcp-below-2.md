# mcp held below 2 until sup7.mcp_server migrates

- **Problem**: `mcp>=1.0` let a fresh install take mcp 2.x, where `FastMCP` became `MCPServer`; `sup7.mcp_server` (Claude Code provider) no longer imports, so `sup7 start` fails as soon as `mcp_server.enabled` is on. void kept working only because its venv still had mcp 1.27. Found by replaying the new CI in a clean venv.
- **Decision**: `mcp>=1.0,<2` in `pyproject.toml`; the ruff rule set is written out (`E4`, `E7`, `E9`, `F`) so a newer ruff judges the code like the local one.
- **Why**: the smallest change that makes a fresh install behave like void; migrating to the v2 API is its own task.
- **Where**: `pyproject.toml`; CI in `.github/workflows/ci.yaml` (Python 3.10 and 3.12, ruff, pytest). Lift the bound when `sup7/mcp_server.py` uses `mcp.server.mcpserver.MCPServer`.
